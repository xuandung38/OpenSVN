# Benchmark: OpenSVN engine vs svn CLI

- svn CLI: svn, version 1.14.3 (r1914484) (1.14.3)
- server: Server version: Apache/2.4.58 (Ubuntu) + mod_dav_svn, HTTP on 127.0.0.1
- dataset: 100000 text files + 4 x 64 MiB binaries, 452 MiB in r1
- machine: 4 CPUs, Linux 6.18.44-fc-v114
- build: release
- repetitions: 3 (median shown, min in brackets)

| operation | svn CLI | engine | engine / svn |
|---|---:|---:|---:|
| checkout HEAD | 36.65 s (33.08 s) | 947.39 s (929.16 s) | 25.85 |
| update r1 -> r2 (10000 files + 1 binary) | 8.97 s (8.15 s) | 82.88 s (81.42 s) | 9.24 |
| status, first run (page cache dropped) | 1.25 s (1.25 s) | 17.08 s (17.08 s) | 13.70 |
| status, repeat run | 0.43 s (0.36 s) | 14.68 s (14.41 s) | 34.04 |
| status, repeat run, each tool on its own checkout | 0.48 s (0.26 s) | 15.05 s (14.64 s) | 31.55 |

- Not slower than svn CLI: **does not hold** for: checkout HEAD; update r1 -> r2 (10000 files + 1 binary); status, first run (page cache dropped); status, repeat run; status, repeat run, each tool on its own checkout
- Repeat status < 3 s on 100000 files: **does not hold** (14.68 s)

Each number is the wall time of a separate process (`svn` or `compare-svn engine`), process start included. Every engine checkout/update is followed by an untimed `svn status` + `svn info` check (clean, right revision).
