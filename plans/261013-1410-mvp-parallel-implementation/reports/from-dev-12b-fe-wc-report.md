## Summary
- Merged `origin/main`: it was already up to date (main is `7e418f6`), so no new merge commit.
- **Fixed the flaky `history.test.tsx` properly.** It was reproduced under CPU load: `findByRole` timed out after 1 s of wall-clock time, and the test then ran out of its 5 s budget. The fix is a shared `installFakeClock()` helper in `src/test-utils.tsx`. It turns on Vitest fake timers for every test, adds the `jest` shim that Testing Library needs to detect them, and binds `userEvent.setup({ advanceTimers })` to the fake clock. With it, `findBy*`/`waitFor` budgets count simulated time, not wall-clock time. No test is skipped. The per-test timeout is now only a hang guard (30 s for history). The PR's own `wc-changes`/`wc-dialogs` tests have the same problem, so they use the same helper, with a 120 s hang guard because each test boots the whole window and needs 10-20 s of CPU.
- **Backend `tooComplex`:** added `FileDiff.too_complex: Option<bool>` (`opensvn-ipc`). The app's `DiffOptions` has a new field, `full_text`. FakeEngine runs `svn_diff::diff` with `DISPLAY_MAX_COST` (it now depends on `svn-diff`). When the diff goes over that budget, it sets `tooComplex: true` and leaves out `left`/`right`.
- **Backend `diff_external { target: DiffTarget }`:**
  - The configured `diff.externalTool` is checked again before every launch: the program must still exist and be executable, and the args must pass validation. If no tool is configured, the command returns `invalidArgument` with action `openSettings`. Binary files are refused.
  - Both sides are written as read-only copies into a fresh folder, `<data>/external-diff/<uuid7>/{left,right}/<safe name>`. The private folder uses the same checks as `preview` (`prepare_private_dir`). Copies older than 24 h are swept on the next launch.
  - The tool is started without a shell. `{left}`/`{right}` placeholders in the args are replaced; if neither is present, both paths are appended.
  - Launching goes through a `ProgramLauncher` trait, so tests use a recorder. The command is registered in the command registry, command names, capabilities (`allow-diff-external`), and the autogenerated permission.
- **Contract:** doc 03 now covers `FileDiff.tooComplex`, `diff_external` and the arg placeholders. `bindings.ts` was regenerated (`pnpm gen:ipc`).
- **FE:**
  - The DiffView uses `diff.tooComplex`; the client-side `estimateDiffCost`/`isTooComplex` heuristic was removed.
  - "Open in external tool" calls `diffExternal` and shows a toast with the backend message on error. The same button was added to the large-file banner.
  - The history revision diff sheet offers the external tool for too-complex or too-large diffs.
  - The mock adapter implements `diffExternal`, `programChoose` and `programClear`.
- **12a leftover (small):** Settings > Diff & Merge "Choose…/Clear" now calls `program_choose("diff-tool", args)` / `program_clear`. Rust shows the native picker and the confirmation; the WebView never sends a path.
