# 12c Repository manager (Current repository picker, checkout into a new folder, File menu)

Date: 2026-10-13 · Branch `feat/12c-repo-manager` (from `feat/12b-fe-wc-m1`, PR #73; #73 head `48c8776` merged in) · Worktree `/home/user/wt-12c`

## What the user gets (UX for the PO)
- **Toolbar "Current repository ▾"** (always visible, `Ctrl+T` / `Cmd+T`, also File › Switch Repository…). It opens a search-first list of every registered working copy: name, end of the folder path, server host, and when it was last opened (most recent first). Type to filter, use ↑/↓ and Enter to switch (the app opens the working copy: recovery runs, then status loads).
- **Row actions:** right-click, the ⋯ button, or `Shift+F10`. You get Reveal in file manager, Copy URL, Rename… (display name only, stored in the app database; the folder keeps its name) and Remove from list…. Remove asks first and says that files stay on disk.
- **Missing or moved working copies** stay in the list with a "Missing" warning and a tooltip. Enter or the menu offers **Locate…** (pick the new folder in the native dialog; it must be the same repository) or Remove.
- **The footer** has "Checkout repository…" and "Add existing working copy…".
- **Checkout dialog:**
  - URL field with recent repositories as suggestions, and **Browse…** to pick a folder from the repository tree.
  - Revision (HEAD or a number), scope (depth) and ignore externals.
  - Destination is **parent folder + folder name**. The parent defaults to Settings › General "Default checkout folder" (`~/svn`); "Change…" picks another one natively. The name is suggested from the URL (`…/game/trunk` → `game`) and validated as you type. Reserved Windows names, separators, `..` and trailing dot or space are refused. A preview shows "Creates …/name".
  - After Checkout, the dialog shows progress with **Cancel checkout** and **Continue in background**. When it finishes, the new working copy is registered, opened and made current, and a toast "Checked out X" appears. Sign-in and certificate prompts appear on top through the existing prompt host.
- **Settings › General:** "Change…" for the default checkout folder now works (native folder dialog).
- **Native menu bar:**
  - File: Checkout Repository… `Mod+Shift+O`, Add Existing Working Copy… `Mod+O`, Switch Repository… `Mod+T` (on Windows/Linux also Settings… and Quit).
  - Edit: the standard items.
  - On macOS, an app menu.

## Backend (Rust)
- New commands:
  - `wc_entries`: every registered working copy, including missing ones (`missing`, `problem`, `lastOpenedAt`, `addedAt`, `url`).
  - `wc_locate { wcId, grant }`: same repo UUID required; refuses a root that is already registered elsewhere; spends no grant on an unknown id.
  - `recent_urls`
  - `checkout_root_grant`: Rust mints a Dir grant for `general.checkoutRoot`, expands `~` and creates the folder.
  - `checkout_root_choose`: native folder dialog that stores the setting.
- **`reveal_in_os`** is implemented: path relative to the working copy, `""` = root, checked with `RelPath`; `tauri-plugin-opener::reveal_item_in_dir` behind a `FolderRevealer` trait.
- **`CheckoutRequest.destName`** (`wc/checkout_target.rs`):
  - The name is validated *before* the grant is redeemed, so a typo does not spend the user's folder choice.
  - The target is created with `create_dir`. An existing empty folder is reused; non-empty folders, files and symlinks are refused.
  - On failure or cancel, a folder this checkout created is removed only while it is still empty.
- **`OpResult::CheckedOut { wcId, newRev }`**
- **`general.checkoutRoot` is now a Settings-only "picked" key.** `SettingsPatch` no longer carries it, because a WebView could otherwise launder an arbitrary folder into a grant through `checkout_root_grant`. This is enforced by a serde test, a settings unit test and the IPC ACL test.
- **DB:** `WcRow` has `added_at` and `last_opened_at`; new `wc_set_root` and `recent_url_list`. No migration was needed: the columns already existed.
- **Native menu** (`menu.rs`) emits `menu://<id>`. The FE ignores a menu event that arrives within 400 ms after the same action ran from the keyboard (accelerator echo).
- **FakeEngine:** `simulate_moved_wc(from, to)`.
- **Contract:** capabilities and autogenerated permissions; `bindings.ts` regenerated; doc 03 (§3.1, §3.3, §3.5, §3.6, new §3.7 menu, events, settings) and doc 01 (toolbar, File menu) updated.

## Remaining / notes
- Not verified in a real WebView:
  - native `<datalist>` suggestions on WebKitGTK
  - native menu accelerators: the echo de-duplication is a time window
  - `reveal_item_in_dir` on each OS
- Checkout uses only `general.checkoutRoot`/picked parent; "Open recent ▸" (doc 01 §8.2) and grouping by server in the picker are not done.
- Relative times ("5m ago") come from the existing English-only `relativeTime`.
- A working copy whose registration fails after a successful checkout yields `CheckedOut { wcId: null }`. The FE only refreshes the list; the user can still use "Add existing…".
