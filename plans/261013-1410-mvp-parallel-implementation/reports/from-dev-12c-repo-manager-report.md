# 12c Repository manager (Current repository picker, checkout into a new folder, File menu)

Date: 2026-10-13 · Branch `feat/12c-repo-manager` (from `feat/12b-fe-wc-m1`, PR #73; #73 head `48c8776` merged in) · Worktree `/home/user/wt-12c`

## What the user gets (UX for the PO)
- **Toolbar "Current repository ▾"** (always visible, `Ctrl+T` / `Cmd+T`, also File › Switch Repository…). It opens a search-first list of every registered working copy: name, end of the folder path, server host, and when it was last opened (most recent first). Type to filter, use ↑/↓ and Enter to switch (the app opens the working copy: recovery runs, then status loads).
- **Row actions:** right-click, the ⋯ button, or `Shift+F10`. You get Reveal in file manager, Copy URL, Rename… (display name only, stored in the app database; the folder keeps its name) and Remove from list…. Remove asks first and says that files stay on disk.
- **Missing or moved working copies** stay in the list with a "Missing" warning and a tooltip. Enter or the menu offers **Locate…** (pick the new folder in the native dialog; it must be the same repository) or Remove.
- **The footer** has "Checkout repository…" and "Add existing working copy…".
- **Checkout dialog:**
  - URL field with recent repositories as suggestions, and **Browse…** to pick a folder from the repository tree.
  - Revision (HEAD or a number), scope (depth) and ignore externals.
  - Destination is **parent folder + folder name**. The parent defaults to Settings › General "Default checkout folder" (`~/svn`); "Change…" picks another one natively. The name is suggested from the URL (`…/game/trunk` → `game`) and validated as you type. Reserved Windows names, separators, `..` and trailing dot or space are refused. A preview shows "Creates …/name".
  - After Checkout, the dialog shows progress with **Cancel checkout** and **Continue in background**. When it finishes, the new working copy is registered, opened and made current, and a toast "Checked out X" appears. Sign-in and certificate prompts appear on top through the existing prompt host.
- **Settings › General:** "Change…" for the default checkout folder now works (native folder dialog).
- **Native menu bar:**
  - File: Checkout Repository… `Mod+Shift+O`, Add Existing Working Copy… `Mod+O`, Switch Repository… `Mod+T` (on Windows/Linux also Settings… and Quit).
  - Edit: the standard items.
  - On macOS, an app menu.

## Backend (Rust)
- New commands:
  - `wc_entries`: every registered working copy, including missing ones (`missing`, `problem`, `lastOpenedAt`, `addedAt`, `url`).
  - `wc_locate { wcId, grant }`: same repo UUID required; refuses a root that is already registered elsewhere; spends no grant on an unknown id.
  - `recent_urls`
  - `checkout_root_grant`: Rust mints a Dir grant for `general.checkoutRoot`, expands `~` and creates the folder.
  - `checkout_root_choose`: native folder dialog that stores the setting.
- **`reveal_in_os`** is implemented: path relative to the working copy, `""` = root, checked with `RelPath`; `tauri-plugin-opener::reveal_item_in_dir` behind a `FolderRevealer` trait.
- **`CheckoutRequest.destName`** (`wc/checkout_target.rs`):
  - The name is validated *before* the grant is redeemed, so a typo does not spend the user's folder choice.
  - The target is created with `create_dir`. An existing empty folder is reused; non-empty folders, files and symlinks are refused.
  - On failure or cancel, a folder this checkout created is removed only while it is still empty.
- **`OpResult::CheckedOut { wcId, newRev }`**
- **`general.checkoutRoot` is now a Settings-only "picked" key.** `SettingsPatch` no longer carries it, because a WebView could otherwise launder an arbitrary folder into a grant through `checkout_root_grant`. This is enforced by a serde test, a settings unit test and the IPC ACL test.
- **DB:** `WcRow` has `added_at` and `last_opened_at`; new `wc_set_root` and `recent_url_list`. No migration was needed: the columns already existed.
- **Native menu** (`menu.rs`) emits `menu://<id>`. The FE ignores a menu event that arrives within 400 ms after the same action ran from the keyboard (accelerator echo).
- **FakeEngine:** `simulate_moved_wc(from, to)`.
- **Contract:** capabilities and autogenerated permissions; `bindings.ts` regenerated; doc 03 (§3.1, §3.3, §3.5, §3.6, new §3.7 menu, events, settings) and doc 01 (toolbar, File menu) updated.

## Round 2: merge of main (#73 merged) and review 5506451901

`origin/main` merged with a merge commit and no conflicts. The PR no longer depends on an unmerged branch.

### Blocking items
1. **`reveal_in_os` and symlinks.** The new `os_shell::reveal_target` does this:
   - It parses the path with `RelPath::from_server` (server-name rules; `""` means the root).
   - It refuses any component below the WC root that is a symlink: links to outside, links to inside, and dangling links. This matches `has_symlink_component` in the #62 opener.
   - It then uses `safe_join` and canonicalizes both the root and the target with `dunce` (so Windows paths carry no `\\?\` prefix), and refuses a target that is not under the root.
   - It passes the canonical path to the revealer.

   Unix tests cover a directory link to outside (`docs`, `docs/id_rsa`), a file link to outside, a link to inside (`in-link`, `in-link/file.txt`), a dangling link (`dangling`, `dangling/x`), and a WC root that is itself reached through a link. In each refused case the `RecordingRevealer` records nothing. Doc 03 §3.5 is updated.
2. **`wc_locate` with another repository.** The fake engine gets `simulate_repository(root, uuid, root_url)`. The test checks two cases:
   - A WC with a different UUID is refused ("another repository"), and the entry keeps its old `root_path` and `repo_root_url`.
   - The same UUID relocated to another root URL is accepted, and the entry takes the new root URL.

### Non-blocking items
- **`wc_locate`** now stores `repo_root_url` together with `root_path` (`wc_set_root(id, root, url)`).
- **`destName`:**
  - Refuses `.svn` and `_svn` with their case, NFKC, ignorable-code-point and trailing dot/space aliases, plus `SVN~n`. This uses the new `svn_types::is_any_admin_dir_name`, which shares its folding with `is_admin_dir_alias`.
  - Must also pass `RelPath::from_server` segment rules, so it refuses `COM0`/`LPT0` and the superscript digit forms. The local reserved-name copy is removed.
  - Refuses Cf format characters (bidi, zero-width, BOM, soft hyphen, tags). It shares `programs::is_deceptive`, which was widened to the full Cf set.
  - The FE mirror (`validateFolderName`, `isAdminFolderName`) adds the error kinds `tooLong`, `format` and `admin`, each with its own message (en and vi).
- **Echo suppression** now works in both orders: menu then key, and key then menu. Each echo suppresses exactly one event. New tests check that a menu event 401 ms after the key runs, and that a key press 401 ms after a menu event runs.
- **Checkout dialog:**
  - A name refused by the backend (`invalid_argument` whose `detail` is the name) keeps the picked parent; other refusals still ask for it again. This contract is documented on `validate_folder_name` and in doc 03.
  - Side fix: `toAppError` now unwraps `IpcError`. Before, `toAppError(e)` on an `unwrap` rejection returned `internal` and dropped the code and detail; only the message survived.
- **Doc 01 §3.2:** the old "Ban đầu…" sentence is replaced. Server grouping and per-WC counts are now marked as a later phase.

## Round 3: merge of origin/main (#62 P08 M2, #69, #82, #80)

Two merge commits (main at `9129c5f`, then `437bbdc`). Both sides' behavior is kept; overlapping pieces are unified:

- **Menu.** One native menu: main's spec-driven `menu.rs`. The PR's own menu builder is gone. Added `file.switch-repo` ("Switch repository…", Mod+T). Only ids of the spec emit `menu://<id>` (`event_for`), so native items and unknown ids emit nothing (the PR's rule). A failed install is logged, not fatal (the PR's rule). The UI's `MENU_EVENTS` / `MENU_ACTIONS` now use the spec ids (`file.checkout`, `file.add-wc`, `file.switch-repo`, `app.settings`, `wc.update`, ...) and keep the menu/keydown echo suppression. A Rust test reads `src/ipc/events.ts` and fails if the UI subscribes to an id that the menu does not have.
- **Invisible/bidi characters.** One rule: `display_text::is_deceptive`. It is used for program confirmation, checkout folder names, picked names and notifications. `programs::is_deceptive` is gone. Added U+0600–0605, U+06DD, U+070F, U+08E2, U+110BD, U+110CD, U+13430–1343F and U+1D173–1D17A. U+2028/2029 and the Hangul fillers U+115F, U+1160, U+3164 and U+FFA0 were already in main's set. The FE `FORMAT_CHARS` mirrors the same set.
- **Reveal.** One path: `os_integration::reveal_in_os` → `reveal_target`. It refuses a symlink in any component, checks canonical containment, passes the canonical path to the file manager, and returns `path-not-found` for a missing item. The `os_shell` module, `FolderRevealer` and the `revealer` field of `AppState`/`AppDeps` are removed. `SystemOpener::reveal` now uses `tauri_plugin_opener::reveal_item_in_dir` instead of `open -R` / `explorer /select,` / `xdg-open`.
- **AppState.** Main's `opener`, `notifier`, `menu`, `updates` and `secrets` are kept. There is no separate revealer.
- **`checkout_root_choose`.** Both sides added it. The PR's version is kept, because `general.checkoutRoot` is not patchable. Main's duplicate command, registration and capability entry are dropped. Main's test for it passes against the PR's version.
- **Folder names refused by `RelPath::from_server`.** The backend message is now "the name cannot be used for a folder on every supported system". It no longer says "reserved by Windows".
- **Main breakage fixed on the way:** `engine/real/tests/remote_tests.rs` from #80 had an unbiased `tokio::select!`, which #82's `every_select_in_the_app_is_biased` check refuses. Added `biased;`.
